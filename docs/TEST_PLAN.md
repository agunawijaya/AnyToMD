# Test plan

## Test philosophy

The user has a strong preference for "if you can't verify it, don't claim it works." So testing here is behavioral — we generate real fixtures, run the real converters, and inspect the real output. No mocks of the AI. No pytest suite (yet); a smoke script is enough for the current scope.

There are three levels:

1. **Compile check** — `python -m py_compile` on every module after any change. Cheap first-line defense.
2. **Smoke test** — `tests/run_smoke.py` runs every converter against a generated fixture and writes the `.md` to `tests/output/`. Fast enough to run after every meaningful change (~30–40 s wall time on Ollama).
3. **Manual GUI check** — `python -m anytomd`, drag a fixture, look at the preview. Not automated; call this out explicitly when done.

Automated Mermaid validator/autofix unit tests live in the ad-hoc `-c` snippet used during development (see [DECISIONS.md § validator false-positive](DECISIONS.md#mermaid-validator-false-positive)). If a validator regression is suspected, run the snippet in [Validator regression check](#validator-regression-check) below.

## Test scenarios

### S1 — PDF header/footer stripping

**Given**: `sample.pdf` with `"Company Confidential — Internal Use Only"` at top of every page and `"Page N of 3"` + `"Q3 2026 Report"` at bottom of every page.

**When**: `convert_pdf(sample.pdf, ai)`.

**Then**: output `.md` must NOT contain the strings `Company Confidential`, `Page 1 of 3`, `Page 2 of 3`, `Page 3 of 3`, `Q3 2026 Report`. Body sections `Executive Summary`, `Regional Performance`, `Architecture Overview` and their paragraphs must appear in order.

### S2 — PDF embedded image analysis

**Given**: `sample.pdf` page 3 contains `diagram.png`.

**When**: converter runs.

**Then**: output contains a `> **Gambar (diagram):**` line after the page-3 body text. It must contain a description in the document's language mentioning "Start"/"Process"/"End"/"Retry" or their equivalents. If a fenced ```` ```mermaid ```` block is present, its first line must start with a valid Mermaid diagram type keyword and no bad-pattern regex must match.

### S3 — PPTX picture slide

**Given**: `sample.pptx` slide 3 has the diagram picture.

**When**: converter runs.

**Then**: slide-3 section starts with `## Ingestion Pipeline` and has the picture's alt-text line. Slide-number placeholder must not appear, nor any `Layout:` / `Placeholder` line (removed 2026-09-30).

### S4 — PPTX shape diagram

**Given**: `shape_diagram.pptx` slide 1 has 5 shapes + 5 connectors + `Yes`/`No` textbox labels, **no bitmap image**.

**When**: converter runs.

**Then**:
- The connectors resolve (`pptx_shape_mermaid.extract_flow`), so the slide gets the direct Mermaid of S13 — no AI call. The raster + VLM pass only runs when a slide looks like a shape diagram but its connectors resolve to nothing.
- `tests/output/shape_diagram_render.png` is created if `preview_render.py` is invoked — a spot-check for the rasterizer output.
- Shape text ("Commit", "Build", ...) must **not** appear as separate paragraphs — only inside the Mermaid block.

### S5 — DOCX with tables, lists, headings, header/footer, image

**Given**: `sample.docx` with everything.

**When**: converter runs.

**Then**:
- Header text (`"Company Confidential — do not distribute"`) and footer text (`"Q3 2026 Report · Page "`) do **not** appear.
- Title `"Q3 2026 Report"` appears as `## Q3 2026 Report` (level 0 title → H2 in output; the file title `# sample` already occupies H1).
- Headings `Executive Summary` (H1), `Key Metrics` (H2), `Priorities` (H2), `Architecture` (H1) appear at their expected levels.
- The 4-row `Key Metrics` table appears as an MD table with `Region | Bookings (USD M) | YoY Growth` header.
- The `Priorities` list items appear as `- Ship reporting pipeline v2` (dash bullets).
- The embedded image is analyzed and produces a description + valid Mermaid block.

### S6 — XLSX multiple sheets + trimming

**Given**: `sample.xlsx` with three sheets, `Sales` having 2 trailing empty rows.

**When**: converter runs.

**Then**:
- Output contains `## Sheet: Sales`, `## Sheet: Regions`, `## Sheet: Notes` in that order.
- Sales table has exactly 6 data rows (trailing empties trimmed).
- `Regions` table shows `Countries` column as integers (`15`, not `15.0`).
- `Notes` sheet is rendered even though it has only one column.

### S7 — Standalone image

**Given**: `diagram.png`.

**When**: `convert_image(diagram.png, ai)`.

**Then**: output has:
- `# diagram` file title
- `**Jenis gambar:** diagram`
- `## Deskripsi` followed by a paragraph
- `## Diagram (Mermaid)` followed by a valid Mermaid block **OR** `*(Bukan diagram struktural…)*` fallback

### S8 — Mermaid validator regression <a id="validator-regression-check"></a>

Manual smoke script (paste into REPL or a `.venv\Scripts\python.exe -c "..."`):

```python
from anytomd.ai_client import _validate_mermaid, _autofix_mermaid

cases = {
    "valid_paren":       "flowchart TD\n  A[Start] --> B(Process)\n  C -- Yes --> D[End]",
    "valid_curly":       "flowchart TD\n  A[Start] --> B{OK?}\n  B -->|Yes| C[End]",
    "bad_space_bracket": "flowchart TD\n  C [No] --> D[Retry]",
    "bad_qm_id":         "flowchart TD\n  Test --> Pass? [Pass?]\n  Pass? -->|Yes| Deploy",
}
expected = {
    "valid_paren": ("valid", None),
    "valid_curly": ("valid", None),
    "bad_space_bracket": ("valid_after_fix", None),
    "bad_qm_id": ("valid_after_fix", None),
}
for name, src in cases.items():
    ok, r = _validate_mermaid(src)
    if not ok:
        fixed = _autofix_mermaid(src)
        ok2, r2 = _validate_mermaid(fixed)
        state = "valid_after_fix" if ok2 else "invalid"
    else:
        state = "valid"
    exp = expected[name][0]
    print(f"{name}: {state} (expected {exp}) {'OK' if state == exp else 'FAIL'}")
```

All four should print `OK`.

## Docs / doc-sync check (do this after any structural change)

The four docs that describe design intent MUST stay in sync with the code:

1. **CLAUDE.md** — current state, layout, non-obvious things.
2. **docs/VISION.md** — problem, target user, success criteria, non-goals.
3. **docs/ARCHITECTURE.md** — mermaid component diagram + module map.
4. **docs/SPECIFICATION.md** — per-format contract.
5. **docs/DECISIONS.md** — ADR for each meaningful design choice.
6. **docs/ROADMAP.md** — mark completed items with resolution date + reference.
7. **README.md** — public-facing quickstart + benchmark.

If you land a new feature and don't update at least one of these, a future contributor won't know why the feature exists. The reflex: after code change, ask *which of these needs a paragraph?* — usually the answer is "at least DECISIONS + one other."

## Interpreting outputs

- Every `.md` should render clean in VS Code preview / Obsidian / GitHub.
- Mermaid blocks should render — paste into https://mermaid.live/ if in doubt.
- If a Mermaid block is missing where you expected one: the model's raw output was either `NONE` or invalid past autofix + retry. Rerun; if consistently missing, that's a limitation of the model, not a bug.

## Known non-deterministic behaviors

- VLM output text varies across runs at temperature 0.2. Descriptions won't be byte-identical between runs.
- Mermaid presence/absence for a given diagram is stochastic on Ollama. Anthropic is more consistent but still not deterministic.
- First run per session includes Ollama model load (~15–20 s extra on first `analyze_image` call).

Assertions in test scenarios above are **behavioral** (presence/absence of specific text, structure), not exact-match, to accommodate this.
